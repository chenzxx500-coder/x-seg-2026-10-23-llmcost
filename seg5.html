真实案例：把数字代入方程算一遍

光讲方法不够，拿公开价目验算一次。DeepSeek V4.1 Flash，假设一次请求 1500 个输入 token、400 个输出 token：闲时输入 1500×0.15/百万 + 输出 400×0.60/百万 ≈ 0.000465 美元；峰时同样请求 ≈ 0.00093 美元，正好翻倍。一天 1 万次这样的请求，闲时 4.65 美元，峰时 9.3 美元——排班不同，一个月差出 140 美元。这还只是"错峰"一招。

再看缓存：同样 1500 个输入 token，如果 98% 命中缓存（上面提到的 coding agent 实测水平），输入成本从 0.15 美元/百万降到接近 0.003 美元/百万，输入账单直接砍掉 98%。

这就是视频标题里"2000 倍"的由来：10 美元 vs 半美分，是把选对模型、缓存、批处理、错峰全部叠满后的极限差距。单招做不到，叠满才行。

验收动作：四步把这篇文章变成省下来的钱

  1. 先让账单可视：按功能、按模型、按用户把成本归因做出来。看不见的钱，砍不动。
  2. 按投入产出排序：先做一、二、三、五、七——选模型、缓存、Batch、压输出，都是改几行配置的事。
  3. 定指标再动手：用"单次完成任务的成本"做前后对比，别只看 token 数。
  4. 叠加，别单点：每上一招都重新测一次，乘法效应要亲眼看到才算数。

账单不会自己变小，但方程里的每个因子都有人替你写好了折扣。这篇建议收藏——下次看到 AI 账单心跳加速时，回来一条一条对。
