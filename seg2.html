一、按任务选模型：别拿旗舰模型干 mini 的活

这是投入产出比最高的一招，也是最多团队栽跟头的地方。模型选小了效果不够，是显性问题，人人都会发现；模型选大了悄悄多花的钱是隐性问题，没人察觉。一位开发者的实测记录显示：同一模型家族内，旗舰版换到次旗舰能省 50%，换到 mini 级别能省 85%（以其生产数据为准，仅作量级参考）。

落地动作：把请求按难度分三档——分类、摘要、格式转换这类"体力活"走 mini/nano 级；只有真正的复杂推理才上旗舰。每季度用真实生产数据重测一次分档线，模型迭代太快，三个月前的结论会过期。

二、路由与级联：让机器替你选模型

如果请求难度事先看不出来，就别人工分档，让路由层来。做法有两种：路由（router）——先由轻量判断器评估问题难度，再派给对应档位的模型；级联（cascade）——先让便宜模型试，搞不定再升级。RouteLLM 的论文数据显示路由能把成本砍到一半以下，FrugalGPT 的级联方案在测试中最高省掉 98% 的费用（论文数据，实际看你的任务分布）。

落地动作：从 OpenRouter 这类现成路由网关起步，先跑影子流量对比质量，确认无损再切生产。

三、Prompt Caching：重复的前缀只付一次全价

这是所有"低投入"招数里单招最狠的。每次请求里不变的那部分——系统提示词、工具定义、反复引用的长文档——服务商只收一次全价，后续按缓存价计费。Anthropic 与 OpenAI 的官方文档都确认：缓存命中的输入 token 最高能打到 1 折左右。

真实数字看 DeepSeek 的公开价目：V4.1 Flash 闲时，缓存命中的输入 token 是 0.003 美元/百万，未命中是 0.15 美元/百万——50 倍的差距。有实测记录了一个 coding agent 的 613 次请求、1.559 亿 prompt token：因为 agent 每轮都重发同一套长上下文，缓存命中率干到了 98.1%。

落地动作：把 prompt 里不变的部分顶到最前面、一字不差地固定住，变化的用户输入放最后。注意：前缀里塞一个时间戳或请求 ID 就会让缓存彻底失效，有实测的命中率直接掉到接近 0。

四、语义缓存：一样的问题，别付两次钱

Prompt Caching 省的是"同一前缀"，语义缓存省的是"同一个问题"。用户 A 问"退货政策是什么"，用户 B 问"怎么退货"——语义相近，直接复用上次的答案，这一次调用连模型都不用碰。命中一次就省掉一次完整调用的全部费用，生产环境 50%–70% 的命中率并不罕见。

落地动作：对客服、FAQ、站内搜索这类重复度高的问题先上语义缓存；命中率是自己的数据说了算，先测一周再定。
